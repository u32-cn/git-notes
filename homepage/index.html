笔记，应该放在谁那里？

云端笔记很方便，但数据在服务商那边。Git笔记把同一个方便，建在你自己的文件夹上。

云端笔记
  • 数据存在服务商的数据库里
  • 导出格式与迁移方式，由服务商决定
  • 服务停了，笔记也跟着停
  • AI 想读你的历史，要先经过服务商

方便，但钥匙不在你手里。

VS

  • 笔记是你电脑里的一个普通文件夹
  • 每帖一个 Markdown 文件，随时打开
  • 同步走标准 git，远端随时能换
  • 卸载软件，文件夹还在

功能

每天都会按到的按钮。

没有花哨的功能清单，只有写、找、整理、同步这几件事，认真做顺。

发布与编辑

Ctrl + Enter 直接发，每帖最多 9 张图，粘贴截图即可上传。附件单个 10MB 以内，原始文件名保留。

标签与置顶

点标签一键筛选，重要笔记可置顶钉住，最多 9 篇。钉住清单随同步走，所有设备一致。

全库搜索

毫秒级搜索全部笔记，关键词 AND 组合。输入 biji 或 bj 都能命中「笔记」，不用切换输入法。

多端同步

每次写操作自动拉取、写入、提交、推送。优先 rebase，不行再 merge；真冲突会提示，不会静默丢数据。

AI 助手

配置你自己的 API Key，20 多种工具操作。批量删除超过 5 篇时，无论什么模式都强制人工确认。

本地安全

只监听 127.0.0.1，凭证使用随机 cookie 加 Host 校验。SSH 专用 ed25519 密钥，私钥权限 0600。

问答

你可能还想知道。

换电脑了，笔记怎么迁移？

新设备安装 Git笔记，绑定同一个远端仓库，自动拉取全部笔记与历史。整个过程就是一次 git 克隆。

远端服务商可以换吗？

可以。换个仓库地址重新绑定即可，数据是标准 git 仓库，原样带走。

不用远端会丢数据吗？

不会。仅本机模式下数据就在你电脑里，配合 git 历史依然可以追溯和恢复。远端只是额外的备份与同步手段。

误删了笔记怎么办？

每一步操作都是 git 提交，历史里都在。可以让 AI 查 git 历史并恢复旧版本，熟悉 git 的也能直接用命令找回。

AI 功能需要联网吗？

AI 对话需要联网调用大模型服务，需自行配置 API Key；但笔记数据始终留在本地，由本机代理按需读取。

多设备同时改会冲突吗？

正常先后使用几乎不会冲突，自动 rebase 整合。真冲突时会明确提示「冲突待处理」，由你选择以本地为准强制推送。

笔记是什么格式？

普通 Markdown 文件，按 micro/年/月/日期-时间.md 存放，任何编辑器都能打开，永远不会有格式锁死的问题。
